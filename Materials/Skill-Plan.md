### 第一部分：完成项目需要点亮哪些“技能树”？

要完成从算法到版图的完整流程，你们需要接触以下四大模块的知识。**不用害怕，大部分工具不需要精通，只需“够用”即可。**

#### 1. 硬件架构设计（核心逻辑转换）
*   **空间与时间并行（Parallelism）**：软件里写 `for` 循环是一步步算的，硬件里你可以同时放 16 个乘法器一拍算完。如何打破循环、展开计算，是架构设计的核心。
*   **流水线设计（Pipelining）**：把一个长计算（比如几十个乘法加法）切成好几段，中间插寄存器。像工厂流水线一样，虽然单个数据处理时间没变，但整体吞吐量（Throughput）极大提升。
*   **数据缓存（SRAM & Buffer）**：卷积需要滑动窗口，前面的数据不能丢。你们需要学习 **Line Buffer（行缓存）** 或 **Ping-Pong Buffer（乒乓操作）** 的概念，用来在 DWConv 和 PWConv 之间暂存数据。
*   **查找表（LUT）**：Sigmoid 是非线性浮点函数，硬件绝对不会直接算 $e^{-x}$。你们需要预先用 Python 算好输入输出的映射，存成一个 ROM/SRAM 查找表，硬件直接查地址得结果（参考学长的做法）。

#### 2. RTL 代码实现（Verilog）
*   **基础语法**：模块实例化（Module）、时序逻辑（`always @(posedge clk)`）、组合逻辑（`assign`）、状态机（FSM）。
*   **定点数运算**：利用你们量化（重量化）的知识，在 Verilog 里实现截位、算术右移（`>>>`）和有符号数（`$signed`）乘法。

#### 3. 仿真与验证（Verification）
*   **测试台编写（Testbench）**：用 Verilog 写一个“假”的外部环境，给你们的芯片喂时钟信号和数据。
*   **测试向量生成**：这是你们的强项。用 Python/C++ 搭建一个**比特级精准（Bit-accurate）** 的 CNN 模型，导出每一层输入和输出的十六进制文本（`.txt`），在 Verilog 中通过 `$readmemh` 读入比对。

#### 4. EDA 工具链与后端（Synthesis & Physical Design）
*(注：这部分通常助教会提供现成的 Tcl 脚本，你们重点是学“怎么看报告”和“改参数”)*
*   **逻辑综合（Design Compiler）**：把 Verilog 代码翻译成真实的逻辑门（与非门等）。重点学习看**时序报告（Setup/Hold Time 违例）**和**面积/功耗报告**。
*   **物理设计（ICC/Encounter）**：把逻辑门摆放到二维平面上并连线（布局布线）。了解 **Floorplan（布图规划）** 和 **利用率（Utilization）** 对面积指标（Area）的影响。

### 第二部分：8周“边学边做”双线推进策略

因为只有两个人，且时间紧迫，**坚决不要先看书再动手**。建议采取**“大兵团作战与分工结合”**的策略：
*   **同学A（偏算法与验证）**：主攻 Python 数据流比对、Verilog 核心算子（MAC树、LUT）、Testbench。
*   **同学B（偏架构与后端）**：主攻 整体控制状态机（FSM）、SRAM/Buffer 控制逻辑、跑通 DC 和 ICC 工具链。

#### 阶段一：降维打击，锁定架构边界（第 1 周）
**目标：明确你们要设计成什么样，写出黄金模型（Golden Model）。**
1.  **算力指标反推（关键！）**：
    *   高性能场景要求 `1000K` 帧/秒。
    *   假设 0.18um 工艺下，你们综合出来的时钟频率最高只能跑到 `150MHz` - `200MHz` 左右（保守估计）。
    *   这意味着：处理一帧数据（1,30,10），你们**最多只能用 150 到 200 个周期**。
    *   *参考对比*：学长用了 288 个周期。你们必须把他的并行度翻倍（比如每个周期算 2 个 FC 节点，或者增加前级卷积的并行 MAC 数量）。
2.  **发挥软实力**：用 Python 手写这个 CNN（不要用 PyTorch 自带的 Conv，自己写嵌套 for 循环，加上量化截位逻辑），把网络中间**每一层**的结果打印成文本文件。这就是后续查错的“唯一真理标准”。

#### 阶段二：算子级单点突破（第 2-3 周）
**目标：掌握 Verilog 基本盘，实现并验证所有基础模块。**
1.  **边学边写 Verilog**：直接上手写一个 16 路或 32 路并行的“乘累加树（MAC Tree）”。
2.  **实现存储与缓存**：学习并写出一个 Line Buffer。弄懂怎么用移位寄存器保存上一行的数据，供 3x3 DWConv 滑动使用。
3.  **实现查找表**：写一个包含 Sigmoid 映射关系的 ROM 模块。
4.  **跑通仿真**：把 Python 导出的第一层权重和输入喂给你的 Conv1 模块，在 ModelSim 或 VCS 中看波形，**直到你的 Verilog 输出跟 Python 完全一致**。

#### 阶段三：网络拼接与全流水拉通（第 4-5 周）
**目标：将积木拼成大厦，跑通完整的 Testbench。**
1.  **架构连线**：参照学长的架构图（Conv1 -> Buffer -> DWConv -> Buffer -> PWConv -> PostProcess），把你们的算子连起来。
2.  **停顿与握手（Stall & Valid）**：这是零基础最容易踩坑的地方。如果前面的数据没算完，后面的模块不能启动。需要设计简单的使能信号（`valid_in`, `valid_out`）。
3.  **顶层验证**：给顶层模块喂入 100 张随机语音特征图，要求 Verilog 输出的分类结果（0 或 1）与 Python 完全一致。到这里，**功能分已经拿满了**。

#### 阶段四：跨越工具墙，综合与时序分析（第 6 周）
**目标：跑通 Synopsys Design Compiler (DC)，拿到网表。**
1.  **理解脚本**：向助教要上一届的 DC 综合脚本（`.tcl`），主要修改里面的顶层模块名和时钟约束（`create_clock`）。
2.  **解决时序违例（Timing Violation）**：这是必然会遇到的。如果 DC 报错说“Setup time violated”，意味着你们在这个周期里塞了太多的组合逻辑（比如乘法连着乘法）。
    *   *怎么学？* 此时去查阅“流水线切割（Pipeline Register）”的概念，回到 Verilog 代码里，在这两个逻辑之间加一个触发器（寄存器）打一拍，问题就迎刃而解。

#### 阶段五：后端实现与疯狂优化（第 7-8 周）
**目标：生成版图，榨干 PPA（功耗、性能、面积）指标以获取高分。**
1.  **跑通物理设计（ICC/Encounter）**：导入 DC 生成的网表和约束文件，用助教的自动化脚本跑 Floorplan -> Placement -> CTS -> Routing。
2.  **冲刺 FoM (Speed/Area)**：
    *   因为你们选的是“高性能场景”，评分重点是 `Speed / Area`。
    *   你们在第 1 周设定的架构已经保证了极高的 Speed（比如 $\le 150$ 周期完成）。
    *   现在要在物理阶段把 Area 压到最小。学习如何调整 Floorplan 的 Utilization（利用率）参数，只要不出现布线拥塞（Congestion）和时序违例，就把核心面积往死里挤。
    *   **课程拿高分的核心技巧**：把你们“为了满足 1000K FPS 采取的架构妥协”和“后端压缩面积的努力”，详细地写进 PPT 和报告中，展示出你们懂得了 Hardware Trade-off（软硬件协同折中）。
