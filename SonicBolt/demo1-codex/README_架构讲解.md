# Conv1 架构讲解

## 1. 目标与规模
本设计实现 Conv1：

- 输入：`(1, 30, 10)`，INT8
- 卷积核：`(32, 1, 11, 7)`，INT8
- 偏置：`(32)`，INT16
- 输出：`(32, 20, 4)`，INT8（经 Requant + ReLU）

空间位置总数是 `20 x 4 = 80`，每个空间点同时输出 32 通道。

---

## 2. 为什么用 11 行缓冲
卷积核高度是 11，所以任意一个窗口都需要连续 11 行输入。

设计采用 11x80bit 寄存阵列：

1. 每来一行新数据，就整体上移一次
2. 最新行写到底部
3. 根据 `col_cnt=0~3` 从每行切出 7 个字节

这样不需要复杂的横向移位链，控制简单，硬件规则。

---

## 3. 为什么是 32 路 MAC 并发
Conv1 有 32 个输出通道。如果串行算通道，会把吞吐降到 1/32。

所以架构固定：

1. 1 个窗口数据广播给全部通道
2. 32 棵 `MAC_Tree_77` 同时工作
3. 一拍对应一个空间位置（32 通道一起出）

---

## 4. MAC 三段流水拆分
单个通道的 77 项点积拆成三段：

1. `MAC77_Mult`：77 路乘法
2. `MAC77_AddTree_s1`：先做分组求和
3. `MAC77_AddTree_s2`：总和并加 bias

拆分后关键路径明显缩短，更容易跑到课程目标频率区间。

---

## 5. Requant + ReLU 的实现
后处理公式：

`O = (I * 356) >>> 16`

然后做激活与饱和：

1. `<0` 置 `0`
2. `>127` 置 `127`
3. 其余保留低 8 位

该处理单元是 2 级流水，并行复制 32 路。

---

## 6. 顶层调度策略
FSM 使用：

`IDLE -> LOAD_WEIGHT -> FILL_LB -> CALC_RUN -> DRAIN -> DONE`

关键点：

1. `LOAD_WEIGHT` 连续装载 32 组权重/偏置
2. `FILL_LB` 先读满 11 行
3. `CALC_RUN` 用 `row_cnt/col_cnt` 走完 20x4
4. `col_cnt==3` 时请求下一输入行更新 LB
5. `DRAIN` 等待流水线尾部数据全部吐出

---

## 7. 吞吐理解（本实现）
理想情况下（忽略外部等待）：

1. 80 个窗口对应 80 次有效计算发射
2. 每次发射得到 32 通道输出
3. 输出顺序是 `row-major` 空间顺序，通道顺序 `ch0..ch31`

外部 SRAM 有等待时，会在行切换处引入停顿，但功能正确性不受影响。
